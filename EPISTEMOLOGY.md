# Part I — Ontology
## What Exists

---

### The Governing Law

UMH exists to maximize justified capability.

It does not optimize for novelty.
It does not optimize for imitation.
It does not optimize for intelligence alone.

It optimizes for the continuous accumulation
of verified, composable capability grounded
in reality.

Every observation is evidence.
Every model is a hypothesis.
Every execution is an experiment.
Every outcome updates the organism's
approximation of reality.

---

### Reality as Source

Reality is the singular source of all knowledge.

Reality contains:
- Objects
- Relationships
- Dynamics
- Constraints
- Feedback

UMH observes those. Then it extracts
first principles, primitives, relationships,
invariants, and variables.

Everything below that is operationalization.

---

### The Core Statement

UMH does not operationalize human knowledge.
It operationalizes reality.

Human excellence is treated as evidence —
a high-quality approximation of reality —
not as truth itself.

The system decomposes that evidence into
first principles, primitives, and invariants,
validates them across multiple domains,
and only then reconstructs them into governed,
high-leverage execution.

This prevents the system from treating any one
expert, framework, or organization as canonical.
It treats them as observations.

The canonical layer is the underlying structure
that multiple successful systems independently
converge upon.

# Part II — Epistemology
## How the Organism Acquires Justified Understanding

---

### The Acquisition Pipeline

The pipeline is circular. Outcomes feed back
into reality. The organism's understanding
continuously refines.

```
Reality
↓
Observe Reality
↓
Observe Excellence
↓
Extract Evidence
↓
Decompose
↓
First Principles
↓
Primitives
↓
Relationships
↓
Invariants + Parameters
↓
Models
↓
Operationalize
↓
Verify
↓
Refine
↓
Reality
```

---

### Excellence is One Dataset

Excellence is a particularly valuable source
of evidence. It is not the only one.

Reality contains many sources:
- Failures
- Evolution
- Markets
- Biology
- Physics
- Economics
- Organizations
- Psychology
- Software
- Ecosystems

All of these are observations.

This prevents the system from becoming
overly anthropocentric. Human excellence is
signal. Reality is the domain.

---

### The Knowledge Hierarchy

UMH structures knowledge in layers.
Higher layers govern lower layers.
Lower layers are derived from higher layers.

```
Reality
↓
First Principles         (fundamental truths)
↓
Primitives               (irreducible building blocks)
↓
Patterns                 (recurring arrangements)
↓
Systems                  (interacting patterns)
↓
Frameworks               (organized systems)
↓
Strategies               (application toward objectives)
↓
Playbooks                (context-specific execution)
↓
Actions                  (individual operations)
```

The system reasons downward from principles
to actions — never upward from actions to
principles. Actions are outputs, not inputs.

---

### Invariants

An invariant is a causal relationship that
continues to predict outcomes across
sufficiently different domains, scales,
and implementations.

An invariant is not "three people did this."

It is a mechanism that independently emerges
in unrelated systems. When three or more
domains converge on the same mechanism,
confidence increases that something
fundamental has been found — not merely
a local optimization.

Example:

*Continuous feedback loops with local autonomy
and global standards outperform centralized
inspection.*

That invariant appears in:
- Toyota Production System
- Kubernetes reconciliation
- Git version control
- CI/CD pipelines
- Lean Startup methodology
- Human nervous systems
- Biological evolution
- UMH execution loops

Different domains. Same primitive.
That is the level UMH learns at.

# Part III — Cognition
## How the Organism Reasons

---

### Top-Down Reasoning

The organism reasons from principles to actions.
Never from actions to principles.

Instead of: "Copy the Toyota Production System."

UMH asks:
- Why does TPS work?
- What are its primitives?
- Where else do those primitives exist?
- Can multiple independent domains be explained
  by the same primitive?

This is the difference between copying
and understanding.

Copying produces brittle reproduction.
Understanding produces adaptive mastery.

---

### Continuous Refinement

Knowledge in UMH is never final.

Every invariant is a hypothesis validated
by cross-domain convergence.

When new evidence contradicts an invariant,
the invariant updates — not the evidence.

When a primitive fails in a new domain,
that failure is signal:
either the primitive was not truly fundamental,
or the domain has a constraint that reveals
a deeper primitive underneath.

Both outcomes improve the system.

# Part IV — Operationalization
## How Understanding Becomes Governed Execution

---

### The Template Model

A template is not a document.
A template is not knowledge.

A template is an executable parameterized
structure. It is closer to a function
than a file.

```
Template = f(invariants, parameters, context) → specific solution
```

Definition:

*A template is an operationalized mapping
between invariants and variables that becomes
executable only when instantiated with context.*

---

### Template Anatomy

Every template contains five components:

```
Invariants        what cannot change
↓
Parameters        what may change (degrees of freedom)
↓
Constraints       what is allowed
↓
Objective         what success means
↓
Execution Graph   how it runs
```

---

### Capability Template vs Capability Instance

**Capability Template** stores:
- Invariant structure
- Parameter slots
- Constraints
- Execution graph
- Verification criteria

Never changes per user.

**Capability Instance** stores:
- User context
- Current state
- Goals
- Resources
- Environment
- Instantiated parameters

Unique every time.

---

### The Runtime Cycle

```
Capability Template
+
Reality Context
↓
Instantiate
↓
Capability Instance
↓
Execute
↓
Measure
↓
Refine Template
```

---

### What Users Actually Do

The user does not ask UMH to execute
a workflow. The user instantiates capability.

```
User Intent
↓
Context
↓
Instantiate Templates
↓
Compose Workflows
↓
Activate Skills
↓
Run Loops
↓
Harness Adapters
↓
Execute
↓
Verify
↓
Learn
```

A prompt is context. It fills in variables.

- "Write me an email" = instantiate the
  communication capability template with
  my context.
- "Build software" = instantiate the software
  engineering template.
- "Deploy infrastructure" = instantiate the
  DevOps template.
- "Negotiate a deal" = instantiate the
  negotiation template.

The user never interacts directly with first
principles or primitives. They interact with
instantiated capabilities.

UMH's job is to decompose reality until it
discovers the invariant structure, encode that
structure into reusable templates, and then
instantiate those templates against the user's
current reality under governance.

---

### The Unified Capability Stack

Everything in UMH is a manifestation of the
same underlying concept at different scales:

*A capability is an operationalized template
derived from reality.*

The hierarchy:

**Primitives** describe reality.

**Templates** encode reusable capability.

**Skills** are reusable capability templates.
A skill transforms capability.

```
Writing Skill
↓
Invariant: Good writing communicates intent.
↓
Parameters: Audience, Purpose, Tone, Medium
↓
Template
↓
Skill
```

**Workflows** compose skills.
A workflow is multiple instantiated templates
connected together.

```
Research → Planning → Writing → Review → Publish
```

Each step is a template. Together they become
a workflow.

Workflow = composed template graph.

**Loops** add feedback and recurrence to workflows.

```
Observe → Decide → Execute → Measure → Learn → Observe
```

Loop = workflow + feedback + recurrence.

**Adapters** connect capabilities to external systems.
The adapter internalizes mastery.
The tool performs actions.

**Harnesses** are a specialized class of adapter
that encapsulate and govern external intelligence
systems (Claude Code, Codex, Gemini CLI, etc.).

Harness = intelligence adapter + capability.

**Agents** select, compose, and execute capabilities
in pursuit of objectives.

Agent = capability orchestrator.

**The Organism** coordinates all agents and
capabilities into one governed, continuously
learning system.

The complete stack:

```
Reality
↓
Evidence
↓
First Principles
↓
Primitives
↓
Relationships
↓
Invariants + Parameters
↓
Templates
↓
Skills
↓
Workflows
↓
Loops
↓
Capabilities
↓
Agents
↓
Organism
```

Nothing is disconnected.
Everything emerges from the layer above it.

---

---

### Mastery Defined

Mastery is not memorization.

Mastery is the ability to decompose reality
into primitives, recognize invariants across
domains, compose those invariants into new
capability, and repeatedly produce excellent
outcomes under governance.
