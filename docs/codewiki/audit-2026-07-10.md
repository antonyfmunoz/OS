# Consolidated Codebase Audit — 2026-07-10

Snapshot audit of `/opt/OS` at commit `a5f09e48e`, produced alongside the
CodeWiki by 14 parallel audit agents + a deterministic full-tree inventory.
Every count below reconciles against `_manifest.json`
(verifier: `scripts/verify_codewiki.py`).

## 1. Executive summary

UMH is a **real, running production substrate** — not a prototype. The
platform contract is frozen (PLATFORM_SPEC v1.0.0), one canonical governed
runtime handles all state changes, six Docker services + host processes run
live on the VPS, and a fleet topology (VPS orchestrator + Windows Beast
executor + Fly.io cockpit + mobile) is operational.

The audit found **no broken core**: the layer laws hold (enforced by
pre-commit gates), the canonical runtime is singular, intelligence routing has
a working deterministic fallback chain. The dominant problems are
**hygiene and drift**, not architecture: 36GB of archive data violating Node
Role Discipline on the lightweight VPS, a 311-commit-stale knowledge graph on
main, runtime state written into source directories and git tracking, and a
possible session-credential file in `services/`.

## 3. What the system is (verified)

- **One canonical mutation runtime** — `governed_mutation → MutationRouter →
  GovernedExecutionSpine`, declared in `substrate/organism/canonical_runtime.py`
  (66 lines, deliberately small). Distinct from the 8-stage LLM cognitive
  pipeline in `substrate/execution/spine.py` — conflating them is the #1
  reader trap. Details: [architecture.md](architecture.md).
- **Most load-bearing file**: `substrate/types.py` — 85 inbound dependency
  edges, the single most depended-on node in the repo; `substrate/execution/cpu_gate.py`
  second (64 in / 0 out). Canonical type registry
  (`substrate/canonical_types.py`) actually registers ~1,157 types (docs say
  ~1040 — stale figure).
- **Intelligence routing**: `adapters/models/model_router.py::call_with_fallback`
  — cc_sdk (Opus via subscription, $0 API) → Gemini 2.5 Flash → Groq → Ollama,
  with deterministic-first fallbacks throughout.
- **Operator surfaces**: Discord (`services/discord_bot.py`, primary) and the
  cockpit (Electron/React/Capacitor; 80 panels, 81 Zustand stores, 112
  components measured). Traces: [data-flow.md](data-flow.md).
- **Runtime footprint**: 6 Docker services + host processes (mesh WS :8094,
  vision relay) + managed crontab + systemd units + Fly.io cockpit.
  Live snapshot: [services-runtime.md](services-runtime.md).

## 5. Doc-reality gaps (docs say X, code enforces Y)

1. **Dependency direction is stricter than documented**: the gate
   (`scripts/check_dependency_direction.py`) also bans substrate → adapters
   imports; CLAUDE.md and architecture-layers.md only mention transports/
   services. The gate is right; docs undersell it.
2. **Type registry count**: docs cite ~1040 canonical types; measured ~1,157.
3. **Tool-mastery skill count**: informal figures said ~140; ground truth is
   **97 skills** (254 files including reference dossiers) under `skills/tools/`.
4. **Committed build output**: `cockpit/src/renderer/dist/` (hashed JS bundle)
   is committed into the source tree — at odds with Node Role Discipline's
   build-artifact stance.
