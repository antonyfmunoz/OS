# `data/` — runtime state, generated knowledge artifacts, and organism memory

**40,487 files · ~38.5 GB · [Full file inventory](../inventory/data.md)**

*(Counts as of the manifest's `generated_at` 2026-07-10T20:18Z, git SHA `a5f09e48e`. `data/` is a live-drift rollup — these are append-only stores and generated caches that change continuously.)*

## Purpose
`data/` is UMH's runtime state root: everything the organism writes about itself while running, plus the large derived knowledge artifacts the cognition stack precomputes. It is not source code — it is the substrate's persistent memory and its generated indices. Two things dominate the file count: `codebase_pages/` (35,582 generated graph pages) and `umh/organism/` (append-only JSONL event/message/journal logs plus workcell heartbeats). Most of `data/` is either regenerable (graph, palace, summaries, pages) or append-only operational state; only a curated slice of audits, reports, proofs, and registries is meant to be tracked in git.

## How it fits
`data/` sits below all code layers — it is written by `substrate/` (organism, control_plane, execution, observability), `adapters/`, `transports/`, and `scripts/`, and read back by the cognition stack at session start. The retrieval hierarchy in `CLAUDE.md` (Palace → Graph → Summaries → Raw Source → Logs) is literally a walk over files in this directory: `data/palace.json`, `data/codebase_graph.json`, `data/node_summaries.json`, `data/codebase_pages/`. No code imports `data/`; code opens paths under it at runtime, resolved from `UMH_ROOT` (default `/opt/OS`) per the no-hardcoded-paths rule.

## Key components
- `data/codebase_graph.json` — source of truth for every structural query. `scripts/query_graph.py` reads it; `codebase_pages/` is rendered from it. Rebuilt end-to-end by `scripts/update-graph`.
- `data/palace.json` + `knowledge/palace/` — the memory palace entry point, first stop in the retrieval hierarchy.
- `data/umh/organism/events.jsonl` and siblings — the organism's append-only life record; written by `substrate/organism/*`, consumed by the reality graph and supervisor.
- `data/umh/instance.json` — BIS-loaded instance values (org, venture, AI name). This is the instance-context boundary made concrete: code stays tenant-free, this file carries identity.

## Data & state
Reads/writes are all file-based (JSON + JSONL). The rebuildable indices (`codebase_graph.json`, `node_summaries.json`, `codebase_pages/`, `merged_graph.json`, `palace.json`) are regenerated by `scripts/update-graph`. The organism JSONL stores are append-only and grow with every execution; `substrate/observability/jsonl_rotation.py` provides line-count rotation (default 5,000 lines) for the stores that opt into it. Neon Postgres is the durable store for traces and agent/skill registration — `data/` is the local operational mirror, not the system of record for those.

## Gotchas
- **Tracked vs gitignored is subtle.** `.gitignore` excludes the big derivables: `data/codebase_pages/`, `data/codebase_graph.json`, `data/node_summaries.json`, `data/merged_graph.json`, `data/codebase_graph_merged.json`, `data/umh/traces/`, `data/umh/memory_candidates/`, `data/umh/mesh/`, `data/umh/rooms/`, `data/runtime/`, `data/semantic_space/`, several `data/*.jsonl` runtime logs, and `data/vault/memory/{conversations,summaries}/`. Tracked slices include `data/audits/`, `data/reports/`, `data/proofs/`, `data/registries/`, `data/sessions/`, `data/snapshots/`, `data/repos/`, `data/work_queue/`, and the `data/logs` symlink itself.
- **`data/umh/organism/*.jsonl` are still tracked despite the `data/umh/organism/*.jsonl` gitignore rule** (lines 111–113). Git only stops *new* files from being added — these were committed before the rule, so they keep showing as Modified in `git status` on every organism tick. `deliverables.jsonl`, `events.jsonl`, `messages.jsonl`, `execution_journal.jsonl`, `outcome_learning.jsonl`, `reports.jsonl`, `dev_sessions.jsonl`, `learning_signals.jsonl` are all in this state. Do not "fix" this by committing their churn.
- **`data/vault/` ≠ top-level `vault/`.** They are two different directories. The gitignore `data/vault/memory/...` rules apply only to `data/vault`. See [`vault/`](vault.md).
- **Node role discipline** (`.claude/rules` / CLAUDE.md): the VPS is the coordination brain — it must not accumulate archive dirs, old proofs, or ingestion intermediaries. `data/` is exactly where that debt collects; audit before it grows.
- **Never estimate `data/` file counts.** Per the Inventory & Audit Verification Protocol, count with `find` — the 40,487 here is a manifest snapshot and drifts every tick.
