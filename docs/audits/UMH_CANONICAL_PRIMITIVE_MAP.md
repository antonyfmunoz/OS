## 1. What "canonical primitive" means here

UMH is a human-governed agentic control plane for desired-state reconciliation across software, data, humans, organizations, workflows, filesystems, cloud services, local devices, runtime nodes, agents, adapters, sensors, and actuators. Its metamodel is organized in four layers:

- **L1 — External Operational Reality Model**: entities outside UMH that the control plane observes or acts on.
- **L2 — UMH Platform Metamodel**: the platform's own primitives (signals, operations, policy decisions, proofs, traces, memory, capabilities).
- **L3 — Projection Domain Models**: domain objects owned by product projections (EOS, CreatorOS, LyfeOS) built on the substrate.
- **L4 — Semantic Grounding/Mapping Layer**: entity resolution, domain bridging, and state-authority (source-of-truth) mapping between the other layers.

A **canonical primitive** is a metamodel type that has exactly one owning definition, is registered in the type registry so the divergence gate can protect it, has test coverage, and is the type every consumer imports. For a reconciliation control plane, these primitives are load-bearing: if two modules disagree on what a WorkPacket or a PolicyDecision is, the control plane cannot guarantee that governance, tracing, proof, and rollback all attach to the same object.

This document maps 33 primitives (the audit brief's canonical set) to their current owners, enumerates competing implementations, and assigns each a status verdict:

| Status | Meaning |
|---|---|
| `canonical-clean` | One registered owner, no same-name rivals, tested. |
| `canonical-but-contested` | A designated canonical exists, but unregistered same-name rivals or parallel lifecycles compete with it. |
| `fragmented` | Multiple parallel definitions with no single owner and no mapping contract between them. |
| `fragmented + broken` | Fragmented, plus verified import-time failures in the affected path. |
| `missing` | The concept is pervasive in prose/fields/stages but no type exists anywhere. |

## 2. The two-parallel-type-modules problem

Two modules under `substrate/` share responsibility for the type system, and the split is the root mechanism behind most fragmentation below:

- **`substrate/types.py`** (1,400 lines) — the de-facto domain type module: ~90 Pydantic models and enums, including `SignalEnvelope` (line 48), `Intent` (753), `WorkPacket` (929), `Signal` (990), `Role` (1108), `ProjectionContract` (1363).
- **`substrate/canonical_types.py`** (1,349 lines) — not a type-definition module at all: a name→module **registry** consumed by the pre-commit divergence gate (`scripts/check_type_divergence.py`). It defines no classes.

Three structural failures follow from this arrangement (evidence in ledgers B1–B4):

1. **The registry is incomplete exactly where fragmentation is worst.** Types defined in `substrate/types.py` itself are unregistered: `Signal` (990), `Intent` (753), the `WorkPacket` class (929 — only its enums are registered at canonical_types.py:74-75). None of B2's eight execution-plane primitive names (WorkPacket, ExecutionStep, AdapterCall, ToolCall, RuntimeNode, RuntimeSession, AgentRole, AgentInstance) is registered by exact name. Zero registrations for ApprovalPacket, MemoryCandidate, ProofArtifact, MutationSpec. All 12 `template_registry.py` types, `ProjectionContract`, `DomainBridge`/`DomainProjection`/`BridgeRegistry`, and the entire `substrate/reality_model/` package are absent. The registry indexes accretion history, not a metamodel. (GAP-B1-011, GAP-B3-004, GAP-B4-005)
2. **The homonym policy is a sanctioned fragmentation vector.** `substrate/canonical_types.py:91-97` explicitly sanctions two canonical types named `Capability` (a BaseModel in `substrate/types.py:658` and an Enum in `substrate/execution/runtime/capability_router.py:36`), and the canonical name `Projection` (canonical_types.py:295) is owned by a state **forecast** (`substrate/organism/projection_engine.py:346`) while the product-projection concept has no canonical name at all. (GAP-B4-001, GAP-B4-007)
3. **A `LEGACY_DUPLICATES` allowlist** (`substrate/canonical_types.py:1296` region, 17 modules) grandfathers acknowledged divergence — self-described technical debt with no convergence burn-down artifact. The registry even carries stale entries: canonical_types.py:1296 claims the environment packet enums were "renamed to EnvironmentPacket* — no longer conflicts," but the actual classes in `nodes/environments/work_packet.py:19,32,39` carry a doubled `EnvironmentEnvironmentPacket*` prefix (a mechanical rename applied twice), and `.claude/rules/type-coherence.md` cites a third set of names matching nothing. Three sources of truth, zero agreement. (GAP-B2-002, GAP-B4-015)

Required convergence posture: `substrate/types.py` (or its successor) is the single L2 definition module; `substrate/canonical_types.py` must register 100% of exported public types; the divergence gate must validate that registry entries resolve to real symbols and must reject same-name/different-module dataclasses (it demonstrably does not today — see RuntimeSession, ProofPackage, MemoryCandidate below).
